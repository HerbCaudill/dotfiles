# Personal environment lifecycle

Home Manager installs the Mac entry point as `drenv`; the implementation is `scripts/devresults-environments/drenv.ts`. See [the user guide](USAGE.md) for installation and commands. All commands select an explicit environment ID. Existing `dr` and `drsync` retain their current behavior.

| Command                                                         | Result                                                                                                                                                                                                                                    |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create <id> --source <Mac checkout> --snapshot <receipt.json>` | Saves creation inputs, pairs frozen source, checks provisioning prerequisites, runs existing build commands, provisions owned data/configuration, and compares the built schema with SQL.                                                 |
| `create <id>`                                                   | Resumes with saved inputs. A previously missing `--snapshot` may be supplied; an established source or snapshot selection cannot silently change.                                                                                         |
| `sync <id>`                                                     | Stops the owned runtime, transfers clean committed Mac HEAD, rebuilds, replaces the deployment, and repeats schema verification. It leaves the environment stopped.                                                                       |
| `start <id>`                                                    | Rechecks source/build/deployment/schema and starts the complete IIS/Azurite runtime. Success requires owned listeners and an HTTP success or redirect with the correct environment/revision headers.                                      |
| `status [id]`                                                   | Lists persisted registry state; an explicit ID also inspects its live Windows supervisor. Persisted state alone is not a live health check.                                                                                               |
| `url <id>` / `open <id>`                                        | Prints the URL or opens it in normal Chrome on the Mac. Existing shared-cookie behavior is intentional.                                                                                                                                   |
| `stop <id>`                                                     | Requests shutdown from the verified supervisor and verifies that its processes and reserved listeners have stopped.                                                                                                                       |
| `snapshot <id>`                                                 | Stops the owned runtime, refuses other SQL sessions, holds its catalog read-only during a checksummed SQL backup and blob copy, then restores write access. Saves a receipt on Windows and in the Mac registry directory.                 |
| `reset <id>`                                                    | Stops the environment, revalidates the immutable original creation snapshot, removes only owned data, restores that snapshot, and repeats the independent schema check.                                                                   |
| `remove <id>`                                                   | Stops owned processes, verifies SQL/files/binding/task/source ownership, removes owned resources and clean source worktrees, and retains the registry tombstone. Snapshots and the shared personal Azurite installation remain available. |
| `recover <id>`                                                  | Explicitly checks Windows ownership and idle state, then releases only provably abandoned Mac locks. It also recovers an interrupted owned read-only snapshot. Retry the original command afterward.                                      |

Creation defaults to the primary native Mac clone and `dev` / `example`. `--preset inl` selects `dev-inl` / `inl`; explicit database and instance selections are supported. A snapshot revision records capture provenance. It may differ from the current frozen source revision. A separately computed current build schema must match the restored database before any application start. Schema receipts preserve both revisions. Automatic database refresh remains disabled.

## Build and startup

The runner invokes `just nuget`, `pnpm install --frozen-lockfile`, `just msbuild-app` and `just build-client` in the owned Windows worktree. It passes `just` a personal dotenv file containing the existing `MSBUILD` and `VSTEST` paths, so no tracked DevResults recipe or configuration needs modification. A build receipt records its source revision and hashes the complete `bin` and Vite output trees. Deployment verification compares the complete artifact set and hashes before startup.

The schema probe compiles a small personal helper against `System.Web` in the owned deployment. An ASP.NET application domain provides the actual hosting paths. Reflection invokes the built application's IOC builder and API registrations, resolves the registered `IVersionStateProvider`, and calls `Compute()`. The result must equal `dbo._Global`'s `SchemaHash` in the owned catalog. This is independent evidence; copying a hash from the snapshot receipt would not satisfy the check. The probe never starts IIS or performs a database refresh.

A passwordless S4U Windows scheduled task launches the supervisor without requiring an interactive desktop session. It needs the user's Task Scheduler logon rights. Its build commands use local resources and public package downloads; S4U does not provide credentials for remote Windows shares. The runtime uses explicit executable paths, an owned IIS configuration, owned temp/storage directories, and private Azurite account configuration passed through the process environment.

Azurite is pinned to `3.37.0` under `C:\DevResultsEnvironments\tools\azurite-3.37.0`. Its marker and package version are checked before use; a foreign tools directory is refused. The normal start command installs this owned dependency when needed and invokes its Node entry point directly. Global `azurite` on SSH's PATH is unnecessary.

Every child starts suspended, is assigned to a kill-on-close Windows Job, and resumes only after assignment. IIS, Azurite and descendants belong to that Job. Stop sends a request containing the environment token and current run ID. Closing the Job stops the whole tree; PID-based global killing is never used. Supervisor receipts include the exact scheduled-task request, PID and process start time. A reused PID or an unexpected task action is refused. The original process handle supplies build exit codes, including very fast exits.

Startup checks all five listeners, including ownership of the three Azurite endpoints. It then requests the application URL and checks the generated `X-Drenv-Environment` and `X-Drenv-Revision` headers. An IIS listener returning HTTP 500 does not count as ready. Redacted failures identify the failing build step/exit code or HTTP status without exposing raw configuration or command output.

## Recovery and boundaries

Mac operation locks cover the complete command. Windows uses one named operation mutex per environment, the host provisioning lock for shared resource mutations, the source-operation lock during recovery, and an OS-owned supervisor process tree. Build, schema, status and stop do not hold the global provisioning lock, so a build does not prevent stopping another environment. Large versioned payloads travel as compressed private SFTP files because Windows SSH stdin handling stalled intermittently during testing. Runtime values remain separate from executable code. Completed transport files are removed after the remote consumer exits; interrupted transfers may leave a uniquely named `drenv-transport-*` directory for inspection.

`recover` never steals a live or ambiguous local lock. It checks that the recorded PID is absent and that the receipt did not change. It first confirms Windows operations are idle; a disconnected SSH client is not evidence that an owned build or restore has stopped. A queued receipt with PID zero still blocks stop, recovery, reset and removal. The runner validates the exact scheduled executable, arguments and working directory, refuses added triggers, and inspects Task Scheduler state before claiming idle. A queued or running Windows task with ambiguous process state remains a concrete inspection prerequisite. No manual JSON edit is needed for ordinary failed command retries or abandoned Mac lock recovery.

An interrupted SQL restore without valid SQL ownership is deliberately refused. Keep its provisioning journal and files intact, confirm the recorded Windows operation has ended, and inspect that exact catalog before explicit SQL recovery. Ownership uncertainty is not permission to adopt or delete a resource. Partial blob copies can be replaced through owned reset once catalog ownership is established. Snapshot state records a transition before making the owned database read-only, allowing `recover` to restore write access after the original process has ended.

A reservation that failed before recording a source revision can be removed only after proving both Mac source/marker and Windows source/store/runtime/claims/catalog/task/process/ports are absent. Any partial pairing resources are preserved for inspection.

Removal first checks Mac source ownership and cleanliness, then completes a read-only Windows preflight for the catalog, runtime, SQL writers, TLS binding, scheduled task, claims, reparse points and Windows source. No catalog or file deletion starts until every preflight guard passes. Local source deletion rechecks its guards. External edits made after preflight can still interrupt the later owned cleanup; preserve the failed receipt and retry after inspection.

Reset and removal are explicit destructive operations on this environment's owned state. They refuse active external SQL sessions, foreign catalog files, foreign bindings/tasks and uncommitted source changes. Ignored build output may be removed with the clean owned worktree. Source preflight checks the root and ancestors for reparse points while allowing normal ignored pnpm links inside the worktree. Before Git cleanup, a traversal of real directories unlinks each source junction or symlink without following it; this preserves targets outside the worktree. A partially completed removal can be retried; completed steps are verified from actual resources before the registry is marked removed.

## Verification evidence and remaining prerequisites

Focused Mac tests cover command ordering, durable creation inputs, conservative checkpoints, snapshot provenance and explicit lock recovery. The real Windows supervisor suite exercises process trees, cross-environment survival, S4U execution, failed children and PID reuse refusal. A tiny owned SQL/blob fixture exercises coordinated snapshotting, foreign-token refusal, reset/drop, checksummed restoration and data preservation. The hosted schema fixture computes the actual registered provider using copied application assemblies while pointing SQL configuration at an unavailable disposable catalog. These tests clean their owned fixtures after the relevant Windows processes exit.

These checks do not prove a complete useful-data DevResults environment. Creation still needs an immutable coordinated source SQL/blob snapshot and enough VM disk capacity for the full SQL allocation, deployment copy, blob data, dependencies and required headroom. Full build/start/browser proof and creation of multiple independent useful environments remain the installation/proof task's responsibility. Existing primary and review runtimes must remain untouched while meeting those prerequisites.
