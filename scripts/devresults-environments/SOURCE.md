# Paired source contract

`pairEnvironmentSource(manifest, sourceCheckout, options?)` freezes the requested revision, creates the native Mac worktree, transports a private Git bundle over SSH/SFTP, and creates an independent Windows bare Git store plus detached worktree. It returns the independently verified Windows commit SHA. `syncEnvironmentSource(manifest, options?)` transfers committed HEAD from `manifest.paths.mac` and fast-forwards only `manifest.paths.windows`. Existing `dr` and `drsync` keep their destinations and behavior.

The lifecycle caller must hold `withEnvironmentLock` for the full operation, validate the manifest through the registry, stop owned runtime processes before changing source, and persist the returned revision with `registry.checkpoint`. The source functions refuse `running` and `removed` phases themselves. Pairing preserves dirty changes in the original source checkout. Both owned worktrees must be clean; sync never makes an implicit WIP commit or discards changes. Commit work in the paired Mac checkout before syncing. Divergent Windows history is refused by Git's fast-forward check. The requested initial revision remains frozen in the source receipt even if the original checkout advances during a retry.

Each source path has a sibling claim directory `<source-path>.drenv-source`, outside tracked application files. Its `owner.json` records `environmentId`, `ownerToken`, the exact `path`, the initial `revision`, and `syncedRevision` after verified transport. The Mac receipt additionally records the canonical original `source` and Git `common` directory. Windows owns `repository.git` inside its claim directory; the Windows primary checkout is never used for bundle fetching or worktree registration. The Windows worktree must resolve its Git common directory to this private repository. Ownership markers alone do not substitute for these path and Git checks.

The Windows payload takes an exclusive file handle on `operation.lock`; the OS releases the handle if PowerShell exits. A leftover unlocked lock file is normal. Uploads use unique bundle names so interrupted copies cannot overwrite another operation's input. Completed uploads are deleted after verification. An interrupted upload can leave an owned bundle in the claim directory; inspection or owned lifecycle removal can clean it up. Local bundle refs are temporary unique refs and are removed in `finally`. A hard-killed Mac process may leave an owned ref or bundle for explicit inspection.

Retry repeats native identity, Git mapping, clean-worktree and revision checks. A crash after Windows fast-forward but before receipt persistence can resume at exactly the requested SHA. An interrupted bare-store initialization can be repeated. A partially checked-out dirty worktree, malformed ownership receipt, missing marker, foreign path, or reused path is refused rather than adopted or erased; inspect that exact owned resource before recovery. Never remove a claim directory while a source operation has it open.

The source layer uses `devresults-vm`, normal native paths, Git, PowerShell 5.1 and SFTP-capable `scp`. It needs enough space for a complete Git bundle, private Windows Git store and checkout. It does not clone SQL/blob data or build source. Application provisioning must separately prove its capacity and runtime prerequisites.

## Focused verification

Run `pnpm exec vitest run scripts/devresults-environments/tests/source.test.ts` for real local Git behavior with a substituted Windows adapter. Run `DRENV_WINDOWS_SOURCE_TEST=1 pnpm exec vitest run scripts/devresults-environments/tests/source-windows.test.ts` for the live SSH/SFTP payload using a tiny disposable synthetic Git repository. The latter verifies real Windows pairing, clean fast-forward, dirty/foreign refusal and receipt interruption recovery. It removes only its uniquely named fixture paths and never edits DevResults tracked files. It proves source transport, not full DevResults creation, database restoration, IIS startup, or cross-environment application behavior.
